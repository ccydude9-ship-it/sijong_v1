# 구현 판단과 검토 결과

2026-10-15. 이 문서는 개발 중 선택한 구현 방법과 남은 보완점을 기록합니다. 현재 결과는 로컬 개발 버전이며, Safari 검사·환경 게시·실제 교실 배포는 완료하지 않았습니다. 실행 방법은 [README](../README.md), 확인 범위는 [검증 기록](VALIDATION.md)을 참고하세요.

## 독립 코드 검토

전체 변경을 별도 검토자가 확인했습니다. 중요한 문제 3개를 실제 영향에 따라 재평가하고, 각각 실패하는 회귀 테스트를 먼저 확인한 뒤 한 차례의 수정 과정에서 해결했습니다. 수정 후 서버 90개·화면 34개·Chromium 13개, 타입 검사·빌드·서식 검사가 통과했습니다. 수정 후 별도 재검토를 반복하지 않았습니다.

1. **이름 변경 실패와 초안 유실:** 홈 이동과 학생 변경을 구분했습니다. 오프라인에서 저장 전 초안이 있으면 다시 저장하거나 변경을 취소하도록 안내합니다. 학생 변경 요청이 실패하면 현재 화면·학생·초안을 유지하고 오류를 표시합니다. 중복 변경 중에는 모드 선택도 잠깐 막습니다.
2. **늦은 충돌 응답이 최신 내용을 덮어쓰는 문제:** 실시간으로 받은 진행 상태와 수업 단계의 버전을 각각 비교합니다. 이전 충돌 응답으로 최신 답이나 수업 종료가 되돌아가지 않으며, 저장된 내용 사용도 최신 확인 상태를 사용합니다.
3. **저장 전 카드로 수업 시작:** 모든 학생 편집기의 수정·그림 업로드·저장 상태를 확인합니다. 저장이나 변경 취소 전에는 시작 버튼을 비활성화하고 이유를 안내합니다. 수업 전환 중에는 추가 편집을 막습니다.

## 개발 중 판단한 사항

아래 목록은 실행 기록의 판단 사항을 순서대로 옮긴 것입니다.

1. 기존 클라우드 체크아웃을 사용했습니다. 승인된 환경 설계와 맞으며 별도 worktree를 만들지 않았습니다. 현재 작업은 `work` 브랜치에 있어 추가 격리 비용은 없습니다.
2. 스킬의 보조 스크립트와 `writing-good-tests.md`가 제공 경로에 없어, 동일한 작업 요약·실패/통과 증거·진행 기록을 로컬 도구로 관리했습니다. 실행을 이어 갈 수 있지만 도구 출력 형식은 원본과 다릅니다.
3. 순수 도메인 타입과 API 계약을 분리하고, 루트 TypeScript 설정 하나와 작은 기능별 저장소를 사용했습니다. 순환 참조와 초기 설정을 줄입니다. 규모가 커지면 저장소와 설정을 분리해야 할 수 있습니다.
4. 그림 연결은 별도 연결 API 대신 학생 카드 8장 저장과 함께 검증합니다. 카드 구성이 원자적으로 저장되고 실패 시 기존 그림을 유지합니다. 교체 업로드 후 연결하지 않은 비공개 그림은 수업 정리 전까지 남을 수 있습니다.
5. Task 9의 새로고침·학생 변경 경쟁·개인 카드 전체 연결은 Task 11의 실제 브라우저 검사에서 확인했습니다. 화면 단위 검사만으로는 연결된 서버 흐름을 증명할 수 없어 통합 검사에 의존합니다. Chromium 검사는 통과했고 Safari 검사는 남아 있습니다.
6. Task 10의 드래그·모드 왕복·모션 감소도 Task 11의 실제 브라우저에서 확인했습니다. jsdom만으로 입력과 배치를 검증할 수 없어 통합 검사에 의존합니다. Chromium 검사는 통과했고 Safari 검사는 남아 있습니다.
7. 공식 브라우저 다운로드가 차단되어 신뢰할 수 있는 사전 설치 Debian Chromium 154를 사용했습니다. 실제 사용 흐름은 확인했으나 Playwright 기본 Chromium 156과 버전 차이가 있습니다.
8. Safari 검사 차단 중에도 독립적인 Task 12 실행·백업 검증을 진행했습니다. 필요한 검사를 삭제하지 않았으며, Safari가 확인되기 전까지 전체 검증 완료로 표시하지 않습니다.
9. 서버는 고정된 `tsx` 실행 도구로 TypeScript 소스를 실행하고, 학생 화면은 Vite로 빌드합니다. SQLite·그림 처리 네이티브 모듈과 마이그레이션 경로를 안정적으로 유지하는 대신, 운영 설치에도 서버 소스와 `tsx`가 필요합니다.
10. 최종 검토용 보조 도구와 `code-reviewer.md`도 제공 경로에서 읽을 수 없어, 같은 범위·영향 기준·설계·계획·진행 기록을 담은 검토 자료를 별도 검토자에게 전달했습니다. 검토를 생략하지 않았으며, 요청 문구의 형식은 원본 양식과 다릅니다.
11. 필수 Safari 검사가 막힌 동안 현재 브랜치와 작업 증거를 보존합니다. 완전한 통과 기록이 없으므로 정리·통합 단계로 넘어가지 않습니다. 남는 비용은 무시된 로컬 검증 파일의 디스크 사용입니다.

## 미룬 작은 보완점

- 같은 이름인 학생 중 한 명의 구별 문구가 비어 있어도, 다른 학생의 구별 문구가 있으면 수업을 시작할 수 있습니다. 예를 들어 `별이`와 `별이 달`은 화면에서 구별됩니다. 설계의 더 엄격한 조건인 “동명이인 모두 구별 문구 입력”을 수업 시작 시 강제하는 보완은 남겨 두었습니다. 같은 이름과 같은 구별 문구의 중복은 이미 거절합니다.
