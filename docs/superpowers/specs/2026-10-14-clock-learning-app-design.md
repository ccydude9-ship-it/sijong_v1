# 시계는 째깍! 하루는 찰칵! — 첫 웹앱 설계

작성일: 2026-10-14

수정일: 2026-10-15 — 오락실 타이틀, 자유로운 모드 선택, 홈 복귀 요구 반영.

상태: React + Node.js + SQLite 구성과 첫 구현 범위 승인 후 작성한 상세 설계. 문서 검토를 거쳐 구현 계획을 작성한다. 이 문서는 구현 완료를 뜻하지 않는다.

## 1. 목적과 기준

초등학교 1학년 학생 6명이 각자의 태블릿에서 오락실 게임 같은 타이틀 화면을 거쳐 자기 이름과 활동 모드를 선택하고, 자신이 만든 일과 카드 8장으로 학습한다. 정각과 30분을 읽고 개인 카드를 시간순으로 배열한다. 교사는 별도 화면에서 학생의 진행 상황과 완성된 일과표를 실시간으로 확인한다. 오류의 위치만 알려 주어 학생이 스스로 수정하도록 한다.

기존 [웹앱 명세](../../WEBAPP_SPEC.md), [체크리스트](../../IMPLEMENTATION_CHECKLIST.md), [README](../../../README.md)의 교육 목표와 활동 흐름을 유지한다. 기본 수업 흐름은 도입 3분, 전개 32분, 마무리 5분이다. 교사가 활동 순서를 말로 안내하고 학생은 메뉴에서 직접 모드를 선택한다. 앱이 활동 모드를 강제로 전환하거나 선행 모드 이수를 요구하지 않는다.

사용자가 승인한 기술 구성은 React + Node.js + SQLite다. 아래의 세부 사항은 이 구성을 구현하기 위한 설계 결정이다.

- 첫 버전은 한 학급, 학생 6명, 교사 1명을 지원한다.
- 외부 서비스 계정 없이 개발 및 자동 검증할 수 있다.
- 공개 저장소와 자동 테스트에는 가명과 가상 일과, 예시 그림만 사용한다.
- 실제 수업에서는 교사가 학생과 함께 고른 일과와 그림을 비공개 서버에 등록한다.
- 학생 화면은 타이틀 → 이름 선택 → 연습·실전·공유 모드 선택 → 선택한 활동 순서다. 학생별 코드 입력 대신 교사가 수업 전에 태블릿을 학급에 연결해 둔다.
- 실제 태블릿에서 접속하려면 공통으로 접근 가능한 서버가 필요하다. 클라우드 개발 머신의 로컬 동작 검증과 수업용 배포를 구분한다.

## 2. 범위

첫 구현은 학생 접속, 무제한 연습, 8장 카드의 시각 입력과 순서 배열, 교사 대시보드, 실시간 상태 전달, 서버 저장과 재접속 복원을 하나의 수업 흐름으로 제공한다. 교사는 수업 시작 전에 학생별 카드의 활동명·그림·시각을 준비하고 확인한다.

교사용 준비 화면은 학생 표시 이름 변경, 학생별 카드 8장 연결·편집, 이미지 업로드, 학급 접속 코드 재발급, 수업 시작을 지원한다. 학습 중에는 카드 수정이 잠기며 수업 종료 후 새 수업을 준비할 수 있다. 수업 기록은 서버에 남고 교사만 열람한다. 초기화는 새 수업을 생성하며 이전 기록을 덮어쓰지 않는다.

다학급 운영, 외부 계정 연동, 공개 자료 공유, AI 기능, 점수 순위표, 인쇄물 제작 도구, 클라우드 배포 자동화는 첫 구현 범위 밖이다. 자동 검증 뒤 실제 기기 사용성 점검과 40분 수업 리허설은 별도 현장 검증으로 남는다.

## 3. 기술 구성과 책임

| 구성 | 선택 및 책임 |
| --- | --- |
| 학생·교사 화면 | React + TypeScript, Vite. 가로 태블릿과 전자칠판에 맞춘 반응형 화면 |
| HTTP 서버 | Node.js 24 LTS + TypeScript + Express. 로그인, 권한 검사, 입력 검증, 학습 판정 |
| 영속 저장 | Node.js 내장 `node:sqlite`의 `DatabaseSync`. 트랜잭션, 외래키, WAL, 제한된 대기 시간 적용 |
| 실시간 전달 | 인증된 SSE(Server-Sent Events). 학생 입력은 HTTP로 보내고 교사 화면에는 변경 상태를 전달 |
| 이미지 처리 | 서버에서 sharp로 PNG·JPEG·WebP를 검증하고 재인코딩하여 메타데이터 제거 |
| 자동 검증 | Vitest로 도메인·API 테스트, Playwright로 브라우저 및 다중 접속 검증 |

Node 24의 내장 SQLite API는 실험적 경고가 있을 수 있으므로 런타임 버전을 고정하고 실제 설치 버전으로 저장·복원 테스트를 수행한다. 학생 6명의 짧은 트랜잭션에 한정하며 여러 서버 프로세스를 운영하는 구조는 사용하지 않는다.

개발에서는 Vite가 `/api` 요청을 Node 서버로 프록시한다. 제품 실행에서는 Node 서버가 빌드된 정적 파일과 API를 같은 출처에서 제공한다. SSE는 지속 연결이며 역방향 프록시를 쓰는 배포 환경에서는 버퍼링을 끄고 연결 제한 시간을 조정한다.

코드는 다음 책임으로 분리한다.

- `apps/web`: 접속 화면, 학생 학습 화면, 교사 준비·진행·공유 화면.
- `apps/server`: API, 인증, SQLite 저장, 이미지 제공, SSE 전달.
- `packages/domain`: 시간 변환, 카드 검증, 시각·순서 판정 같은 부작용 없는 규칙.
- `packages/contracts`: 요청·응답·이벤트 스키마. 서버와 화면이 같은 규약을 사용한다.

npm workspaces와 하나의 lockfile을 사용한다. 저장소는 이미 격리된 클라우드 작업 공간에 있으므로 별도 Git worktree를 만들지 않는다. 제품 의존성 설치와 코드 생성은 설계 및 구현 계획 검토 이후 진행한다.

## 4. 학생 화면과 학습 규칙

### 접속과 공통 조작

선생님이 수업 전에 각 태블릿에서 학급 접속 코드를 한 번 입력하여 기기를 수업에 연결한다. 아이들에게 개인 코드나 비밀번호 입력을 요구하지 않는다. 학생이 앱을 새로 열거나 새로고침하면 아래의 타이틀부터 시작한다. 이미 저장된 학생 세션이 있어도 이름과 모드를 확인할 수 있는 흐름을 유지하며 저장된 학습 진행은 지우지 않는다.

#### 타이틀 — 오락실 게임 시작 화면

화면 가운데에 **시계는 째깍! 하루는 찰칵!** 제목을 가장 크게 배치한다. 그 아래에는 작은 글씨로 **게임을 시작하려면 아무 버튼이나 누르세요**와 보조 문구 **PRESS ANY BUTTON**을 표시한다. 시계·카메라 모티브, 게임 로고 같은 입체감 있는 제목과 완만한 안내 문구 애니메이션으로 오락실 분위기를 표현한다. 한글은 읽기 쉬운 글꼴을 사용하고 빠른 점멸은 피한다. 모션 감소 설정이면 안내 문구도 고정한다.

태블릿은 화면 터치, 마우스는 클릭, 키보드는 Enter·Space를 포함한 일반 입력키로 시작한다. Tab 이동, modifier 단독 입력, 키 반복 입력은 화면 전환을 일으키지 않는다. 화면에는 스크린리더와 키보드로 접근 가능한 실제 시작 버튼 의미도 제공한다. 첫 입력 한 번은 이름 선택 화면까지만 이동시키며 같은 이벤트로 이름이나 모드까지 선택되지 않게 한다. 효과음은 사용자의 입력 이후에만 재생하고 음소거 설정을 따른다.

선생님용 설정·로그인은 별도 작은 버튼으로 제공하고 해당 버튼 조작이 학생 시작 이벤트와 겹치지 않게 한다. 아직 학급에 연결하지 않은 기기에서는 학생 이름을 공개하지 않고 선생님이 기기를 준비하도록 안내한다.

#### 이름 선택 — 내 이름을 골라요

'내 이름을 골라요' 화면에 학생 6명의 이름을 큰 선택 버튼으로 표시한다. 이름 버튼을 누르면 해당 학생에 한정된 세션을 만들고 그 학생이 만든 일과 카드 8장과 저장된 진행을 불러온 다음 **모드 선택 화면**으로 이동한다. 이름 선택만으로 연습이나 실전을 자동 실행하지 않는다. 로그인 처리 중에는 중복 선택을 막고 실패하면 이름 선택 화면에서 재시도를 안내한다.

#### 모드 선택 — 무엇을 해 볼까요?

선택한 학생 이름을 상단에 표시하고 다음 세 개의 큰 모드 버튼을 제공한다.

| 모드 | 화면 문구 | 들어갈 활동 |
| --- | --- | --- |
| 연습모드 | 째깍! 읽어 봐 | 무작위 시계 읽기와 힌트·재도전 |
| 실전모드 | 착착! 맞춰 봐 | 본인이 만든 카드 8장 시각 읽기와 순서 배열 |
| 공유모드 | 찰칵! 들려줘 | 본인의 완성된 일과표 확인 및 발표 준비 |

수업이 시작된 동안 학생은 세 모드를 자유롭게 선택한다. 연습을 마치지 않아도 실전에 들어갈 수 있고, 실전을 완성하지 않아도 공유 화면에 들어갈 수 있다. 아직 결과가 없으면 공유 화면에서 완성된 일과표가 없다는 안내를 보여 주며 정답이나 가짜 완료 결과를 만들지 않는다. 교사가 어떤 모드를 누를지 말로 안내하며 모드별 잠금이나 원격 강제 이동은 제공하지 않는다.

모든 활동 화면의 같은 위치에 **홈으로 돌아가기** 버튼을 제공한다. 여기서 홈은 **현재 학생의 모드 선택 화면**이다. 홈으로 이동할 때 학생 선택을 유지하고 작성 중인 시각·배열을 저장한다. 실전 입력이 틀렸어도 홈 복귀를 막지 않는다. 저장 실패 시 초안을 유지한 채 재시도 또는 저장되지 않은 변경 취소를 선택하게 하고 조용히 입력을 버리지 않는다. 오프라인에는 초안을 메모리에 둔 채 홈을 오갈 수 있으며 새로고침 시 미저장 내용이 사라질 수 있음을 안내한다. 홈 복귀나 모드 왕복만으로 미해결 연습 문제·실전 단계·완료 상태를 초기화하지 않는다. 재진입하면 같은 활동을 이어 한다. 다른 학생으로 바꾸는 '이름 다시 고르기'는 모드 메뉴에서 분리한다. 공유모드는 다른 학생 자료나 교사 대시보드로 학생을 로그인시키지 않는다.

카드는 표시 이름 문자열이 아닌 수업 내 고유 학생 ID에 연결한다. 이름이 같으면 교사가 구별용 표기를 등록하도록 하여 선택 버튼을 구분한다. 학습 화면 상단에 선택한 이름을 계속 표시한다. 이름 선택 화면에는 다른 학생의 그림·일과·진행을 전달하지 않고 이름과 구별용 표기만 제공한다.

'이름 다시 고르기'를 누르면 확인된 진행을 저장한 뒤 현재 학생 세션과 화면 데이터를 정리하고 이름 선택으로 돌아간다. 저장되지 않은 입력이 있으면 저장 재시도 또는 변경 취소를 안내하며 자동으로 다른 학생에게 넘기지 않는다. 다른 이름을 선택하면 이전 학생의 입력·카드·오류 표시를 재사용하지 않는다. 새로고침이나 재접속에서는 타이틀과 이름 선택을 거쳐 같은 학생의 서버에 저장된 진행을 복원할 수 있게 한다.

교사가 수업을 시작하기 전에는 모드 메뉴에 준비 중 안내를 표시한다. 수업 시작 후에는 세 모드가 모두 열리며 개별 모드 개방 절차는 없다. 모든 주요 버튼의 터치 영역은 최소 48 CSS px로 잡고 짧은 한국어 문구를 사용한다. 1024×768 가로 화면을 기준으로 검증하며 작은 화면에서도 내용을 잘라내지 않는다.

빨간 테두리와 함께 짧은 안내 또는 아이콘을 제공해 색만으로 오류를 전달하지 않는다. 키보드 포커스, 버튼 이름, 모션 감소 설정을 지원한다. 효과음은 첫 조작 이후에만 재생하며 끌 수 있다.

### 연습모드 — 째깍! 읽어 봐

- 서버가 1~12시와 0·30분의 24가지 조합에서 무작위 문제를 만든다. 문제 수 제한은 없다.
- 학생은 큰 아날로그 시계를 보고 시·분 버튼을 선택한 뒤 확인한다.
- 오답이면 같은 문제에서 재도전한다. 선택 가능한 힌트는 긴 바늘 강조와 바늘 확대이며 정답 숫자를 표시하지 않는다.
- 정답이면 긍정 피드백을 표시한다. 같은 시·분인 개인 카드가 있으면 카드 앞면을 함께 보여 주고, 없으면 일반 피드백으로 계속한다.
- 같은 시·분의 오전·오후 카드가 둘이면 하루 기준 이른 카드 한 장을 보여 준다. 연습 문제는 오전·오후를 평가하지 않는다.
- 다음 문제는 학생이 버튼을 눌러 시작한다. 같은 문제의 확인을 중복 제출해도 정답 횟수를 중복 집계하지 않는다.

시계는 일관된 SVG로 렌더링한다. 분침 각도는 `minute × 6`, 시침 각도는 `(hour % 12) × 30 + minute × 0.5`다. 30분일 때 시침이 두 숫자 사이에 위치해야 한다. 오답 안내와 접근성 문구에 정답 시각을 넣지 않는다.

### 실전모드 — 착착! 맞춰 봐

1단계에서는 학생 카드 8장을 수업별 무작위 순서로 보여 준다. 카드 터치로 그림과 바늘시계를 전환한다. 그림 영역과 시각 입력 영역을 분리하고 입력 버튼을 누르면 카드가 뒤집히지 않게 한다.

학생은 카드마다 시·분을 입력한다. 아직 입력하지 않은 카드에는 입력 안내를 표시한다. 확인을 누르면 서버가 판정하고 잘못된 카드의 입력 영역만 가는 빨간 테두리로 표시한다. 정답을 제시하지 않으며 수정한 카드의 이전 오류 표시는 다음 확인 전까지 해제한다. 8장 모두 맞으면 2단계로 이동할 수 있다.

2단계에서는 학생이 입력한 시각과 카드별 오전·오후 표기를 참고해 하루의 이른 시각부터 배열한다. 터치 드래그와 함께 '앞으로/뒤로' 버튼을 제공한다. '완성하기'를 누르면 서버가 정답 순서와 비교하여 다른 위치에 놓인 카드 영역에만 오류를 표시한다. 입력 영역에는 순서 오류를 표시하지 않는다.

정답 배열이면 완료 상태와 완성된 일과표를 저장하고 교사에게 알린다. 잘못된 배열은 수정 후 재확인할 수 있다. 1단계로 돌아가 시각을 바꾸면 다시 시각을 확인해야 하며 완료 판정은 해제된다. 교사에게 제출되는 완료 결과는 서버의 시각·순서 판정이 모두 통과해야 한다.

### 공유모드 — 찰칵! 들려줘

학생은 본인의 완성 결과를 본다. 미완료 상태로 들어오면 '실전모드에서 일과표를 완성해 주세요' 안내와 홈 복귀 버튼을 제공하며 입력한 정답을 대신 완성해 주지 않는다. 다른 학생 자료는 학생 화면에 전달하지 않는다. 교사는 대시보드에서 완료한 학생 한 명을 선택하여 일과표를 크게 보여 준다. 교사 화면의 발표 대상 선택은 학생의 현재 모드를 바꾸지 않는다. 실물 양면 카드 발표는 앱 밖의 수업 활동으로 유지한다.

## 5. 교사 화면과 수업 운영

교사는 비밀번호로 로그인한다. 준비 화면에서 6명의 표시 이름과 이름별로 연결된 카드 8장을 확인한다. 실제 수업의 이름은 비공개 서버에서만 관리하고 공개 예시·테스트에는 가명을 사용한다. 교사는 학생이 만든 그림과 일과를 해당 이름 아래에 등록하며 수업 전에 학생과 함께 연결이 맞는지 확인한다. '일어나기'와 '잠자기'는 필수 카드 종류로 관리하고 나머지 6장은 학생이 선택한 일과로 등록한다. 학급 접속 코드는 교사가 태블릿을 준비하는 용도로만 사용한다.

카드에는 활동명, 이미지, 오전·오후, 시, 분이 필요하다. 초기 예시는 저장소에 포함 가능한 가상 그림으로 제공한다. 교사가 올린 실제 그림은 서버의 비공개 저장 경로에 둔다. 검증이 끝나지 않은 학생이 있으면 수업 시작을 막고 해당 항목을 알려 준다.

수업 상태는 `preparing → active → ended`다. 선생님은 수업 전체를 시작·종료하며 연습·실전·공유는 active 동안 학생이 선택하는 화면 모드다. 모드 선택은 수업 상태를 변경하지 않는다. 실전 내부에서만 학생별로 `reading → ordering → completed` 상태를 관리한다. 실전에서 시각을 모두 확인한 뒤 배열하는 학습 규칙은 유지한다. 교사는 완료 학생의 결과를 언제든 발표용으로 열 수 있으며 미완료 학생을 완료자로 표시하지 않는다. 종료 시 미완료 인원을 알려 주고 확인을 받는다. 종료된 수업은 읽기 전용이며 새 학습 판정·저장을 받지 않는다.

진행 대시보드는 학생 6명의 연결 상태, 시각 확인 완료 카드 수, 실전 단계, 완료 여부를 표시한다. 연습 횟수는 학생별 진행 확인용으로만 제공하고 순위나 경쟁 점수로 표현하지 않는다.

준비 중이거나 진행 중인 수업은 서버당 하나만 허용한다. 기존 수업을 종료하거나 준비 중 수업을 삭제한 뒤 새 수업을 만들 수 있다. 새 수업은 마지막 준비 카드의 복사본으로 생성하되 학급 접속 코드를 새로 발급하고 태블릿을 새 수업에 연결한다. 첫 수업은 가상 예시 카드로 시작한다. 이전 수업의 카드·결과는 변경하지 않는다. 교사 전환 명령의 중복 요청은 상태를 두 번 진행시키지 않는다.

## 6. 데이터와 시간 기준

| 데이터 | 핵심 필드 및 제약 |
| --- | --- |
| 교사 | ID, 비밀번호 해시. 초기 버전은 교사 1명 |
| 수업 | ID, 단계, 단계 revision, 학급 접속 코드 검증용 해시, 생성·종료 시각 |
| 학생 슬롯 | 수업 ID, 고유 학생 ID, 슬롯 1~6, 표시 이름 및 구별용 표기 |
| 카드 | 수업·학생 ID, 카드 ID, 활동명, 종류, 이미지 ID, `minuteOfDay` |
| 학생 진행 | 수업·학생 ID, 단계, 입력 목록, 카드 순서, revision, 완료 시각 |
| 연습 문제 | 학생 ID, 문제 ID, 정답 시·분, 해결 여부 및 집계 상태 |
| 세션 | 토큰 해시, 역할(교사·학급 이름 선택·학생), 수업·학생 범위, 만료 시각 |
| 요청 처리 기록 | 수업·학생 범위, operation ID, 요청 해시, 처리 결과 |
| 이미지 | 무작위 ID, 서버 파일명, 형식, 크기, 수업·학생 범위 |

카드 시각의 기준값은 하루의 분 수 `minuteOfDay`다. `오전 12시 = 0시`, `오후 12시 = 12시`로 변환하고 0~1439 범위의 30분 배수만 허용한다. 학생의 읽기 답은 1~12와 0·30으로 판정하고 배열은 `minuteOfDay`로 판정한다.

학생별 카드 8장에는 서로 다른 `minuteOfDay`가 필요하다. 같은 12시간 표기라도 오전·오후가 다르면 허용하고 학생 화면에 오전·오후를 그림과 짧은 문구로 표시한다. 필수 카드 두 종류는 각각 한 장이어야 하며 일어나기가 잠자기보다 이르도록 검사한다. 날짜를 넘어가는 일과는 첫 버전에서 지원하지 않는다.

시각 입력, 판정, 순서, 완료 상태 변경은 한 트랜잭션에서 처리한다. 진행 revision은 학생별로 증가하고 수업 단계 revision은 별도로 관리한다. 클라이언트가 전달한 완료 여부나 정답 순서를 신뢰하지 않는다. 수업별 카드 ID 8장이 중복·누락 없이 포함된 배열만 받는다.

SQLite와 업로드는 기본적으로 Git에서 제외하는 `.local/` 아래에 저장하고 환경 설정으로 외부 영속 디렉터리를 지정할 수 있게 한다. DB 백업은 SQLite backup API로 만들며 실행 중인 DB 파일만 단순 복사하지 않는다. 수업 종료 후 교사가 수업 삭제를 명시적으로 확인하면 관련 진행·세션·그림을 삭제한다. 공유하는 파일은 다른 수업에서 참조하는 경우 보존한다.

진행 변경 요청은 `operationId`, `expectedRevision`, `action`, 입력 또는 카드 순서를 포함한다. action은 `save`, `check-times`, `check-order`, `return-to-reading`으로 제한한다. 서버는 현재 수업 단계와 학생 상태에서 가능한 action인지 검증한다. 성공 응답은 정규화된 본인 진행과 새 revision, 필요한 오류 카드 ID만 반환한다.

operation ID는 같은 학생·수업 내에서 중복 처리를 막는다. 인증·권한 검사 후 이미 처리한 operation인지 먼저 확인하고, 새 요청에만 revision과 단계 검사를 적용한다. 동일 ID와 동일 내용은 저장된 결과를 반환하고 다른 내용이면 거절한다. revision 충돌은 HTTP 409와 최신 본인 상태를 반환한다. 수업 단계가 바뀌어 허용되지 않는 요청도 최신 단계를 포함해 409로 응답한다. 교사 단계 전환에도 별도의 교사·수업 범위 operation ID와 같은 중복 처리 규칙을 사용한다. 입력 형식 오류는 400, 미인증은 401, 권한 없음은 403, 요청 제한은 429다. 학습상의 오답은 HTTP 오류 대신 정상 판정 결과로 반환한다.

학생이 다른 학생 ID를 조작하더라도 학습 API는 선택 완료된 세션에서 범위를 결정한다. SSE와 이미지에도 동일한 권한 검사를 적용한다. 이름 선택용 세션으로 카드·그림·진행에 접근할 수 없다. 학급 코드와 전체 학생 진행은 학생 응답에 포함하지 않는다. 이름 선택 요청은 현재 연결된 학급에 속한 학생 ID만 받으며 임의의 다른 수업 ID를 지정할 수 없다. 종료된 수업에서는 새 학생 선택을 허용하지 않고 수업 종료 안내를 표시한다.

## 8. 접속과 개인정보

교사 비밀번호는 환경 변수 `SIJONG_TEACHER_PASSWORD`로 초기 설정하고 서버가 scrypt와 무작위 salt로 해시하여 저장한다. 초기 DB에 비밀번호가 없으면 교사 계정 생성 없이 서버 시작을 실패시켜 설정 누락을 드러낸다. 비밀번호 변경은 별도 관리 명령으로 처리하고 기존 교사 세션을 폐기한다. 비밀번호 값은 소스·문서·로그에 넣지 않는다.

학급 코드는 암호학적으로 무작위 생성한 8자리 숫자다. 기기 연결은 현재 준비·진행 중인 수업만 대상으로 한다. 서버의 비밀 키를 사용한 HMAC 검증값만 DB에 보관하고 새 코드 원문은 인증된 교사에게 발급 시 한 번 전달한다. 잊어버린 코드나 발급 응답이 유실된 코드는 재발급한다. 코드 원문은 요청 처리 기록에 저장하지 않는다. 서버 비밀 키는 비공개 영속 경로에 한 번 생성하여 보관하고 권한을 0600으로 설정한다.

이름 선택은 선생님이 지켜보는 교실에서 자기 자료를 찾는 방식이며 학생 본인의 신원을 증명하는 개별 인증은 아니다. 연결된 학급의 이름 목록은 선택 과정에서 보이지만 학습 화면은 선택한 학생 자료만 받는다. 개인 계정 없이 이름 선택으로 시작한다는 사용자 요구를 따르며 교사 권한은 별도 비밀번호로 분리한다. 학급에 연결하지 않은 기기에는 이름 목록을 공개하지 않는다.

세션 토큰은 32바이트 난수이며 DB에는 해시만 저장한다. HttpOnly·SameSite=Lax 쿠키를 사용하고 HTTPS 배포에서는 Secure를 적용한다. 세션 유효 시간은 8시간이며 만료 후 교사가 기기를 다시 연결하고 학생이 이름을 선택하면 서버에 저장된 진행을 복원한다. 학생의 '이름 다시 고르기'는 학생 세션을 이름 선택용 세션으로 교체하고, 완전한 로그아웃은 기기의 학급 연결도 해제한다. 학급 코드 재발급과 수업 삭제 시 해당 학급의 이름 선택·학생 세션을 폐기한다. 로그인은 IP 및 코드/계정 단위로 시도를 제한하고 존재 여부를 구분하지 않는 오류 문구를 쓴다.

로그인을 포함한 변경 API는 같은 출처의 Origin을 확인하고, 로그인 이후의 변경 API는 세션에 묶인 CSRF 토큰도 요구한다. 이름 선택과 학생 전환에는 기기 연결 세션 또는 학생 세션의 CSRF 토큰을 요구한다. 요청 크기와 필드를 검증하고 운영 환경은 임의 CORS를 허용하지 않는다. 비밀번호·학급 코드·쿠키·그림·정답 입력을 로그에 남기지 않는다.

업로드는 준비 단계의 교사만 가능하며 파일당 2 MB, 디코딩 후 최대 4096×4096 픽셀로 제한한다. PNG·JPEG·WebP만 허용하고 실제 디코딩으로 형식을 확인한다. SVG와 임의 HTML 업로드는 받지 않는다. 재인코딩한 파일은 무작위 서버 파일명으로 비공개 경로에 저장하고 인증된 이미지 API로만 제공한다. DB와 파일 쓰기 중 실패하면 새 파일을 정리하고 기존 카드 이미지를 보존한다.

실제 배포는 HTTPS, 영속 디스크, 비공개 백업, 동일 출처 설정이 갖춰진 단일 서버를 전제로 한다. 배포할 서비스와 비용은 첫 개발 과정에서 만들거나 확정하지 않는다. 개발 시 가상 자료만 사용하며 실제 학급 자료 등록은 배포 및 접근 제어 확인 이후 한다.

## 9. 실시간 전달과 장애 처리

학생의 변경은 서버 트랜잭션 커밋 뒤에만 완료로 응답하고 SSE로 알린다. 교사는 수업 전체의 요약 스냅샷을 받고 학생은 자신의 진행과 수업 단계만 받는다. 연결 직후와 재연결 직후에는 최신 전체 스냅샷을 보내 누락 이벤트가 있어도 복구한다. 각 스냅샷은 수업 단계 revision과 관련 학생 progress revision을 포함하며 오래된 응답은 화면 상태를 되돌리지 않는다.

SSE에는 heartbeat를 보내며 브라우저 연결 여부를 대시보드에 표시한다. '연결됨'은 학생의 이해도나 활동 완료를 뜻하지 않는다. 정상 로컬 환경에서 저장된 변경이 교사 화면에 2초 이내 반영되는 것을 자동 검증 기준으로 삼는다.

학생 화면은 `저장 중`, `저장됨`, `연결을 확인해 주세요`를 구분한다. 입력은 짧은 지연 후 저장하고 확인·완성 버튼은 최신 입력이 포함된 요청을 보낸다. 미확인 상태에서 완료 안내를 보여 주지 않는다.

네트워크가 끊기면 입력·배열 초안은 현재 화면 메모리에 보존하고 새 판정과 제출을 잠시 막는다. 재연결 시 응답이 유실된 요청은 먼저 동일 operation ID와 동일 내용으로 재전송해 처리 여부를 확인한 뒤 최신 스냅샷을 가져온다. 이미 처리한 응답으로 최신 화면 상태를 되돌리지 않는다. 아직 보내지 않은 작업은 revision이 같고 수업 단계가 유지되면 전송한다. revision이 달라졌다면 서버 상태와 화면 초안을 분리해 보여 주고 사용자가 저장된 상태 사용 또는 초안 재적용을 선택하게 한다. 수업 단계가 바뀌었거나 종료됐다면 새로 적용하지 않고 교사 안내를 표시한다.

페이지를 새로고침하면 서버가 확인한 진행까지 복원한다. 서버가 확인하지 않은 오프라인 초안은 새로고침으로 사라질 수 있다는 안내를 표시한다. 브라우저 localStorage는 서버 저장이나 기기 간 공유를 대신하지 않는다.

DB 쓰기 실패는 성공으로 응답하지 않고 입력을 유지한 채 재시도 안내를 보여 준다. 서버 재시작 뒤에는 DB의 수업·진행을 복원하고 브라우저가 SSE를 다시 연결한다. 종료된 수업의 학생은 완료 결과 또는 종료 안내만 보며 변경할 수 없다.

## 10. 검증과 완료 기준

구현은 테스트를 먼저 작성해 실패를 확인한 후 통과시키는 방식으로 진행한다. 아래의 의미 있는 검증을 구현 계획에 연결한다.

| 검증 층 | 확인할 동작 |
| --- | --- |
| 도메인 | 24가지 시각, 12시 오전·오후 변환, 30분 시침 위치, 중복 시각·필수 카드 검사, 입력·배열 판정 |
| API·DB | 학급 연결·이름 선택·권한·CSRF·요청 제한, 이름 선택용 세션의 자료 접근 차단, 카드 8장 제약, 부당한 상태 전환, 중복 operation, revision 충돌, 저장·복원 |
| 이미지 | 크기·형식 제한, 메타데이터 제거, 다른 학생 이미지 접근 차단, 저장 실패 시 기존 그림 보존 |
| 브라우저 | 교사의 기기 연결 → 오락실 타이틀의 터치·키 입력 → 학생 이름 선택 → 모드 메뉴 → 해당 학생의 활동 → 모드 메뉴 복귀 → 완료 → 교사 공유 |
| 동시 접속 | 학생 6개의 독립 브라우저 context와 교사 1개 context. 진행 분리, 2초 내 대시보드 반영, 타인 자료 차단 |
| 복구 | SSE 단절·재연결, 응답 유실 후 동일 요청 재전송, 두 탭의 충돌, 새로고침·서버 재시작 후 진행 복원 |
| 실행 | TypeScript 검사, 제품 빌드, 빌드 결과로 서버 시작, health 및 대표 학습 요청 검증 |

단위 판정은 오전·오후와 같은 시·분 카드 매칭 규칙을 포함한다. E2E는 학생마다 다른 그림과 활동명을 가진 카드 8장을 등록해 이름 선택이 정확히 해당 카드로 이어지는지 확인한다. 타이틀 입력 한 번이 이름 선택까지만 이동하는지, 이름 선택 다음 화면에 세 모드가 보이는지, 메뉴 왕복이 진행을 지우지 않는지 검증한다. 같은 이름을 가진 학생의 구별용 표기, 이름 다시 선택할 때 이전 학생 데이터 제거, 같은 이름으로 재접속 시 진행 복원을 검증한다. 입력 영역과 카드 영역의 오류 표시가 서로 다른지, 오답 안내가 정답 숫자를 공개하지 않는지도 확인한다. 서버는 테스트마다 분리된 임시 DB·업로드 경로를 사용한다.

1024×768과 좁은 화면에서 주요 조작이 가능하고 키보드로 시·분 선택 및 카드 이동을 수행할 수 있어야 한다. WebKit 테스트로 태블릿 브라우저의 대표 동작도 확인한다. 실제 교실 네트워크, 실물 카드 발표, 1학년 학생의 조작 시간과 40분 수업 리허설은 자동 테스트 결과와 구분해 기록한다.

첫 버전의 개발 완료는 위 자동 검증이 통과하고, 설치·시작·교사 초기 설정·가상 수업 준비·백업 안내가 문서화된 상태다. 제품 배포 완료 또는 실제 수업 적합성을 뜻하지 않는다.

## 11. 개발 실행 계약

구현 계획에서는 Node.js 24를 버전 파일과 engines로 지정하고 npm lockfile을 커밋한다. 설치는 `npm ci`로 재현하고 TypeScript 검사·테스트·제품 빌드를 npm 스크립트로 제공한다. 개발 서버 시작, 제품 서버 시작, 가상 수업 초기화, 비밀번호 변경, 백업 명령은 실행 위치와 필수 환경 변수 이름을 README에 기록한다.

가상 수업 초기화는 실제 수업을 덮어쓰지 않는다. 새 데모 수업을 만들거나 같은 데모 식별자를 안전하게 재사용하며 데이터 삭제를 기본 동작으로 하지 않는다. DB 스키마 변경은 순차 migration을 사용하고 기존 자료를 보존한다.

클라우드 환경의 설치·시작 설정은 해당 명령을 실제로 실행하고 검증한 후 저장한다. 설치된 파일과 프로세스 재시작 지침을 구분하고, 다음 작업에서도 현재 체크아웃을 사용한다. 설계 문서 검토 후 구현 계획을 작성하며 계획 검토와 실행 방식 선택 뒤 제품 코드를 구현한다.
