# 시계는 째깍! 하루는 찰칵! ⏰📸

초등학교 1학년 수학 **시계 보기(몇 시, 몇 시 30분)**를 학생의 실제 하루 일과와 연결하는 학습형 웹앱 프로젝트입니다.

> 상태: **실행 가능한 첫 개발 버전**. React + Node.js + SQLite로 구현했습니다. [검증 결과와 남은 항목](docs/VALIDATION.md)을 확인하세요. 실제 교실 배포와 학생 사용성 검증은 별도입니다.

## 처음 실행하기

Node.js **24.19.0**과 npm이 필요합니다. 터미널에서 이 저장소 폴더를 연 뒤 다음 순서로 실행합니다.

```sh
npm ci
cp .env.example .env
npm run teacher:password
npm run seed:demo
npm run build
npm start
```

`teacher:password`에서 선생님이 사용할 비밀번호를 8자 이상 입력합니다. 입력 내용은 화면에 표시하지 않습니다. `.env`에 비밀번호를 저장하지 않아도 설정한 비밀번호의 해시가 DB에 보관됩니다. 비밀번호를 잊으면 서버를 종료하고 같은 명령으로 새로 설정합니다. `SIJONG_TEACHER_PASSWORD` 환경 변수로 초기 설정하는 방법도 지원하지만 이미 저장된 비밀번호를 자동으로 바꾸지는 않습니다.

기본 서버는 이 컴퓨터의 3000번 포트에서 실행됩니다. 개발 중 화면 자동 갱신이 필요하면 `npm run dev`를 사용합니다. 이때 화면은 5173번, API는 3000번 포트를 사용합니다. 서버가 정상인지 `/api/health` 요청으로 확인할 수 있습니다.

### 선생님이 수업 준비하기

1. 첫 화면의 **선생님 입장**에서 설정한 비밀번호로 접속합니다.
2. 준비 화면에서 학생 이름 6개와 학생마다 연결된 일과 카드 8장을 확인합니다. 기본 자료는 가명과 예시 그림입니다.
3. 실제 그림이 준비되면 **그림 바꾸기**로 PNG·JPEG·WebP 파일을 등록하고 **이 학생 저장**을 누릅니다. 그림은 파일당 2 MB, 최대 4096×4096 픽셀입니다.
4. 일어나기·잠자기는 필수이며 나머지 6개는 학생이 선택한 일과로 바꿉니다. 오전·오후를 포함한 같은 하루 시각이 중복되지 않도록 준비합니다.
5. **학급 코드 새로 발급**으로 코드를 한 번 확인하고 각 태블릿을 해당 수업에 연결합니다. 다시 발급하면 기존 기기도 다시 연결해야 합니다.
6. 준비가 끝나면 **수업 시작하기**를 누릅니다. 앱에서 모드를 잠그지 않으며 선생님이 활동 순서를 말로 안내합니다.

### 학생이 활동하기

**오락실 타이틀 → 화면 터치 또는 키 입력 → 내 이름 선택 → 연습·실전·공유 모드 자유 선택** 순서입니다. 이름을 고르면 그 아이의 카드와 저장된 진행을 불러옵니다.

각 활동의 **홈으로 돌아가기**는 같은 아이의 모드 선택 화면으로 돌아갑니다. 모드를 바꾸어도 이미 저장한 진행과 작성 중 초안은 유지합니다. 아직 일과표를 완성하지 않았다면 공유 화면에 안내를 표시합니다. 이름을 바꾸려면 모드 메뉴의 **이름 다시 고르기**를 사용합니다.

네트워크가 끊기면 새 판정·제출은 잠시 기다리고 초안은 현재 화면에 유지합니다. 연결이 돌아오면 저장 상태를 확인해 이어 갑니다. **서버에 저장되기 전 새로고침하면 미저장 초안은 사라질 수 있습니다.** 다른 화면과 저장 내용이 충돌하면 저장된 내용 사용 또는 초안 재적용을 선택합니다.

### 실제 태블릿에서 사용하기

개발 머신의 로컬 동작 확인과 실제 교실 배포는 다릅니다. 여섯 태블릿이 접근할 수 있는 **하나의 서버**, HTTPS, 영속 디스크와 백업이 필요합니다. 운영 시 `NODE_ENV=production`, 실제 HTTPS 주소인 `SIJONG_PUBLIC_ORIGIN`을 설정하고 필요에 따라 `HOST`를 변경합니다. SQLite를 사용하므로 서버 프로세스는 하나만 운영합니다.

이름 선택은 선생님이 지켜보는 교실에서 자기 자료를 찾는 방식이며 개별 학생의 본인 인증은 아닙니다. 학급에 연결하지 않은 기기는 이름 목록과 그림·진행에 접근할 수 없습니다. 교사 기능은 별도 비밀번호로 보호합니다. 실제 학생 자료는 비공개 서버에만 등록하고 Git에 올리지 않습니다.

## 저장·백업·새 수업

기본 데이터 경로는 Git에서 제외한 `.local/`입니다. `SIJONG_DATA_DIR`로 영속 디스크의 다른 경로를 지정할 수 있습니다. SQLite DB뿐 아니라 **그림 폴더와 `server.key`도 함께 보존**해야 합니다.

서버를 종료한 뒤 다음 명령을 실행합니다.

```sh
npm run backup
```

기본적으로 `.local/backups/` 아래에 새 백업 디렉터리를 만듭니다. 백업에는 `sijong.sqlite`, `images/`, `server.key`, `manifest.json`이 들어갑니다. 이미 존재하는 대상 디렉터리는 덮어쓰지 않습니다. `SIJONG_BACKUP_DIR`로 새 대상 경로를 지정할 수 있습니다. 서버와 관리 명령의 동시 변경은 잠금 파일로 막습니다.

복원하려면 서버를 종료하고 기존 데이터를 별도로 보존한 후, 백업의 DB·그림·키를 **새 데이터 디렉터리**로 함께 복사하고 `SIJONG_DATA_DIR`을 그 경로로 설정해 시작합니다. 실행 중인 SQLite 파일만 단순 복사하지 않습니다. 비밀번호와 기존 진행은 함께 복원됩니다.

수업 종료 뒤 교사 화면의 **새 수업 준비하기**를 누르면 기존 카드 설정을 새 수업으로 복사하고 진행은 새로 시작합니다. 이전 수업 기록은 덮어쓰지 않습니다. 새 수업에는 코드를 다시 발급하고 기기를 연결합니다. `seed:demo`는 이미 있는 예시 수업을 보존하며, 진행 중인 실제 수업이 있으면 덮어쓰지 않고 중단합니다.

## 개발·검증 명령

```sh
npm run typecheck
npm test
npm run test:web
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

브라우저를 설치할 때 공식 다운로드 주소 `cdn.playwright.dev`, `playwright.download.prss.microsoft.com` 접근이 필요할 수 있습니다. CI는 Chromium과 WebKit을 모두 검사합니다. 이 클라우드 머신에는 Chromium이 이미 설치되어 있어 이를 사용하며, Safari 계열 검사 결과는 검증 기록에서 별도로 구분합니다.

설계는 [상세 설계](docs/superpowers/specs/2026-10-14-clock-learning-app-design.md), 작업 순서는 [구현 계획](docs/superpowers/plans/2026-10-15-clock-learning-app.md)에 있습니다. 각 클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 사용하고 별도 worktree를 만들지 않습니다.

## 프로젝트 목표

- 바늘시계에서 정각과 30분을 스스로 읽고 오류를 수정하기
- 학생이 직접 고른 일과 8가지를 시각과 연결하고 시간 순서대로 정리하기
- 각자의 하루를 공유하며 자신이 소중하게 여기는 시간이나 생활 다짐 이야기하기
- AI·디지털 도구를 수단으로 활용하여 **학습자 주도성(의도성·자기조절·자기성찰)**을 기르기

## 학습자 제작 카드

- 학생마다 총 **8장**, **일어나기·잠자기 필수 + 6장 자유 선택**
- 그림은 아이가 직접 그리고, 카드 앞면에는 그림·일과 이름을 배치
- 뒷면에는 해당 일과를 나타내는 **바늘시계** 배치
- 태블릿에서 카드를 터치하면 앞면과 뒷면이 전환됨
- 학생별 실제 생활을 조사한 후 정각 또는 30분 시각으로 교육적으로 연결
- 8장 카드의 시간이 가능한 한 서로 다르게 배정되어 순서 배열에 혼동이 없도록 준비

## 구현 시 주의

6대의 학생용 태블릿과 교사용 대시보드 사이에 **실시간 공유**가 필요합니다. 브라우저 로컬 저장소만으로는 기기 간 동기화되지 않으므로 서버/실시간 데이터 저장소를 사용해야 합니다.

이 공개 저장소에는 학생 실명, 학생 그림, 생활 시각과 같은 **개인정보가 포함된 실제 학습 데이터를 업로드하지 않습니다.** 예시 데이터는 가명·가상 일과를 사용합니다.

## 현재 자산 상태

수업안 원본 PDF, DOCX와 학생들이 실제로 만든 그림·카드 디자인은 별도 작업물입니다. 개발용 예시 그림은 코드에서 생성하며, 실제 그림은 준비된 뒤 교사 화면에서 비공개 서버에 등록합니다. 공개 권한을 확인한 자료만 저장소에 추가합니다.
